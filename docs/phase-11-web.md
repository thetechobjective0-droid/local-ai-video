# Phase 11 — Local Web API + Dashboard

## Purpose

Phase 11 adds a thin browser interface over the existing local-first generation services. The web layer does not implement generation algorithms; it loads persisted project state, invokes existing application services, and exposes persisted artifacts.

## Launch

Start the dashboard from the repository root:

```bash
uv run video-agent-web
```

The server binds to `127.0.0.1:8765` by default. Open `http://127.0.0.1:8765/` in a browser on the same machine.

The application refuses generation operations when `runtime.local_only` is disabled. The web server itself is loopback-only by default and does not provide a cloud upload path.

## API surface

### Health

`GET /api/health`

Returns the local-only service status.

### Projects

- `GET /api/projects` — list persisted projects.
- `POST /api/projects` — create a Director plan using the configured local Ollama provider.
- `GET /api/projects/{project_id}` — return project metadata and storyboard scenes.
- `POST /api/projects/{project_id}/resume` — resume an incomplete Director plan.

### QA and timeline

- `GET /api/projects/{project_id}/qa` — run deterministic project QA and persist `qa-report.json`.
- `GET /api/projects/{project_id}/timeline` — return persisted `timeline.json`.
- `GET /api/projects/{project_id}/subtitles/srt` — serve `subtitles.srt` when present.
- `GET /api/projects/{project_id}/subtitles/vtt` — serve `subtitles.vtt` when present.

### Scene artifacts

- `GET /api/projects/{project_id}/scenes/{scene_id}/artifacts` — return persisted artifact manifests and browser URLs.
- `GET /api/projects/{project_id}/scenes/{scene_id}/image` — serve the scene PNG.
- `GET /api/projects/{project_id}/scenes/{scene_id}/audio` — serve the scene WAV.
- `GET /api/projects/{project_id}/scenes/{scene_id}/video` — serve the scene MP4.
- `POST /api/projects/{project_id}/scenes/{scene_id}/regenerate` — regenerate one image, audio, or video stage and rerun QA.

### Final output

`GET /api/projects/{project_id}/video` serves the persisted `final.mp4` artifact.

## Browser dashboard

The dashboard provides:

- local project creation and project selection
- project status and metadata
- storyboard scene timing and narration
- persisted image, audio, and scene-video previews
- scene-level regeneration controls
- QA status and failure details
- timeline visibility
- SRT/WebVTT navigation
- final MP4 playback

The UI is deliberately dependency-free browser JavaScript embedded in `app/web_ui.py`; no frontend build system is required.

## Artifact safety

Artifact endpoints resolve paths beneath the selected project directory before serving files. The API does not accept an arbitrary filesystem path from the browser. Artifact metadata is read from the persisted scene manifests generated by the application services.

## Long-running operations

Generation endpoints are synchronous in the current Phase 11 implementation. The browser disables controls while a request is active and reports failures returned by the API. Background job queues and persistent job-status tracking are intentionally deferred to a later phase rather than duplicating orchestration inside the web layer.

## Local-first constraints

- Ollama requests remain loopback/local according to the existing provider policy.
- Image, TTS, video, QA, timeline, subtitle, and rendering logic remains in existing application modules.
- No automatic media upload or telemetry is introduced by the web layer.
- Generated artifacts remain in the configured project store.
